# Web Application Detection Rules

## Overview

The SOC lab includes custom Splunk detections built on telemetry generated by ModSecurity and the OWASP Core Rule Set (CRS).

Web application attack telemetry is collected from the DVWA (Damn Vulnerable Web Application) environment and forwarded into Splunk through the Universal Forwarder.

These detections enable analysts to identify, investigate, and respond to common web-based attack techniques while providing visibility into attacker behavior and application-layer threats.

---

## Detection Coverage

### SQL Injection Detection

Detects SQL injection attempts identified by ModSecurity and OWASP CRS.

**MITRE ATT&CK**

* T1190 – Exploit Public-Facing Application

---

### Cross-Site Scripting (XSS) Detection

Detects reflected and stored XSS attack attempts against the web application.

**MITRE ATT&CK**

* T1059 – Command and Scripting Interpreter

---

### Command Injection Detection

Detects attempts to execute operating system commands through vulnerable web application parameters.

**MITRE ATT&CK**

* T1059 – Command and Scripting Interpreter

---

## Telemetry Source

All detections rely on:

* ModSecurity Audit Logs
* OWASP CRS Rule Matches
* HTTP Request Metadata
* Apache Web Server Logs

Splunk Index:

```text
index=waf
```

Source Type:

```text
sourcetype=modsecurity:json
```

---

## Validation Environment

The detections were validated using attack simulations performed against DVWA.

Examples include:

* SQL Injection
* Cross-Site Scripting (XSS)
* Command Injection

All testing was performed inside a controlled lab environment.
