# Command Injection Detection

## Overview

This detection identifies command injection attempts against the web application by analyzing ModSecurity audit logs generated by the OWASP Core Rule Set (CRS).

Command injection vulnerabilities allow attackers to execute operating system commands through vulnerable application parameters, potentially leading to remote code execution, system compromise, data theft, and lateral movement.

The detection was validated using attack simulations against DVWA (Damn Vulnerable Web Application) within the SOC lab environment.

---

## Detection Logic

The detection monitors ModSecurity audit logs for command execution indicators and known command injection patterns.

The search looks for evidence of:

* Command Injection signatures
* cmd.exe execution attempts
* PowerShell execution attempts
* Bash and shell execution attempts
* wget and curl download activity
* Command chaining operators
* Shell expansion techniques

When a matching event is identified, the search extracts:

* Source IP address
* HTTP request method
* Requested URI
* User-Agent string
* Triggered ModSecurity rule ID
* HTTP response status code
* Attack outcome (Blocked or Allowed)

Additional metadata is added to support alert triage, investigation, dashboarding, and automation workflows.

## SPL Query

```spl
index=waf sourcetype=modsecurity:json
| eval src_ip='transaction.remote_address'
| eval transaction_id='transaction.transaction_id'
| eval uri='request.request_line'
| rex field=uri "^(?<http_method>\w+)\s+(?<clean_uri>[^\s]+)"
| eval user_agent='request.headers.User-Agent'
| eval message=mvindex('audit_data.messages{}',0)
| eval full_msg=mvjoin('audit_data.messages{}'," ")
| rex field=message "\[id \"(?<rule_id>\d+)\"\]"
| rex field=full_msg "code (?<status_code>\d+)"
| search message="*Command Injection*" OR message="*cmd.exe*" OR message="*powershell*" OR message="*system(*" OR message="*exec(*" OR message="*bash*" OR message="*sh*" OR message="*wget*" OR message="*curl*" OR message="*;*" OR message="*&&*" OR message="*||*" OR message="*`*" OR message="*$(*"
| eval alert_name="Command Injection Attempt Detected"
| eval severity="critical"
| eval risk_score=85
| eval alert_type="web"
| eval asset_type="webapp"
| eval mitre_tactic="Execution"
| eval mitre_technique="T1059"
| eval webapp="DVWA"
| eval dest_host='transaction.local_address'
| eval index_name="waf"
| eval event_source="ModSecurity"
| eval event_id=rule_id
| eval alert_id="WAF-CMD-" . rule_id . "-" . strftime(_time,"%Y%m%d%H%M%S")
| eval timestamp=strftime(_time,"%Y-%m-%d %H:%M:%S")
| eval attack_outcome=if(status_code="403","blocked","allowed")
| table _time alert_id timestamp alert_name severity risk_score alert_type mitre_tactic mitre_technique src_ip dest_host webapp http_method clean_uri status_code attack_outcome user_agent message event_source event_id index_name transaction_id
| sort - _time
```

## Detection Workflow

1. An attacker submits a malicious command injection payload to the DVWA application.
2. ModSecurity inspects the HTTP request.
3. OWASP CRS identifies the payload as a command injection attempt.
4. ModSecurity generates an audit log entry.
5. Splunk ingests the WAF telemetry.
6. The command injection detection search identifies the event.
7. An alert is generated and forwarded to the SOC automation pipeline.
8. Analysts can investigate the alert through Grafana dashboards.

---

## Validation Method

The detection was validated using multiple command injection payloads against DVWA.

Example payloads:

```bash
127.0.0.1; whoami
```

```bash
127.0.0.1 && ipconfig
```

```bash
127.0.0.1 | net user
```

```bash
127.0.0.1; powershell.exe Get-Process
```

```bash
127.0.0.1 && cmd.exe /c dir
```

During testing, OWASP CRS generated ModSecurity alerts which were successfully ingested and detected by Splunk.

## Security Impact

Successful command injection attacks may enable:

* Remote Command Execution
* Privilege Escalation
* Malware Deployment
* Credential Theft
* Data Exfiltration
* Persistence Mechanisms
* Lateral Movement

Detecting command injection attempts at the WAF layer helps prevent attackers from reaching later stages of the attack lifecycle.

## Notes

This detection leverages both OWASP CRS signatures and common command execution indicators to identify malicious attempts to execute operating system commands through web application inputs.

All testing was performed inside a controlled lab environment for educational and defensive security purposes.
